# Scalability Review: ba-auto-ship-service (prod)
**Date**: 2026-11-20
**Reviewer**: DevOps Scalability Reviewer

---

## 1. Executive Summary
ba-auto-ship-service is a tier-1 core-ng microservice in the Blue Apron consumer domain responsible for subscription auto-shipment lifecycle management, automated weekly cart generation, order assignment, fulfillment event processing, and customer delivery scheduling. The application exposes synchronous customer-facing cart modification APIs, back-office administration interfaces, and asynchronous Kafka message consumers that process order creation, inventory reassignment, and fulfillment updates. It is deployed in the prod-ba-consumer namespace across three specialized deployment profiles handling web traffic, background task consumption, and assignment simulations.

Over the lookback window, the service demonstrated outstanding compute stability, near-zero HTTP error rates, and full compliance across all service level objectives with virtually undisturbed error budgets. Stateless compute utilization remains conservative across all pods, operating well below allocated CPU and memory requests with no container restarts or out-of-memory terminations. However, significant persistence layer risks exist, characterized by massive growth in historical fulfillment event tables within MySQL and sharp query targeting degradation during unindexed MongoDB cleanup operations.

1. **Unbounded MySQL Fulfillment Event Table Growth**: The primary fulfillment event table `auto_ship_cart_fulfillment_events` has expanded to 31.37 GB without automated archiving or partitioning, representing a major storage and scaling bottleneck on the shared database.
2. **Severe MongoDB Query Targeting Spikes on Cleanup**: Collection cleanup operations trigger extreme query targeting degradation with a peak of 2090.72 documents scanned per returned document due to a dropped timestamp index on the tracking collection.
3. **Transient MongoDB Peak Read Latency Degradation**: Cluster-level read operations experienced intermittent latency spikes reaching a peak of 128.87 ms during heavy query execution intervals.
4. **Elevated Kafka Consumer Lag on Rebalance Events**: Consumer lag on `auto-ship-rebalance-event-message` experienced burst spikes reaching a peak of 1756 messages during catalog rebalances, exceeding the normal real-time threshold.
5. **Over-Allocated Pod CPU and Memory Requests**: Baseline pod resource consumption averages only 0.0378 CPU cores and 543.76 MiB of memory, leaving requested pod allocations substantially underutilized on the AKS node pool.
